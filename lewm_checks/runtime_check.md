# Cube reference-evaluation runtime check

Status at 2026-09-24 06:30 Beijing: all 12 released-evaluator/wrapper pairs completed and meet the predeclared outcome-agreement criterion. The three Cube pairs and Reacher seed 44 completed under Mesa EGL after the runtime and observer corrections described below. Scores and per-seed outcomes are reported in official_repro.csv and parity.csv; this note documents execution provenance.

The unchanged released evaluator aborted during the first environment step in each of the three 50-query Cube runs. Pinning the EGL device to the CUDA worker did not remove the failure. A separate run using the evaluator's random-policy option reproduced the abort; another reproduced it without initializing CUDA in that process. Both random-policy runs are excluded from study tables.

A native debugger captured `SIGABRT` raised by `libnvidia-eglcore.so.535.161.08`, called from `mujoco.mjr_readPixels`. This localizes the immediate failure to graphics execution. It does not establish a planner error, nor does it prove the specific driver-internal cause. A comparable compute/rendering conflict is documented by the [OpenWAM authors](https://github.com/OpenWAM-Official/OpenWAM/blob/main/benchmarks/libero-plus/README.md); that is supporting context, not a substitute for this diagnosis.

The same host also supplies Mesa EGL. Enumeration identifies device 8 as the software device (`EGL_VENDOR = Mesa Project`); devices 0–7 are hardware devices. The runtime-only workaround selects that EGL implementation with `MUJOCO_EGL_DEVICE_ID=8`, `__EGL_VENDOR_LIBRARY_FILENAMES=/usr/share/glvnd/egl_vendor.d/50_mesa.json`, and `LIBGL_ALWAYS_SOFTWARE=1`. The released `eval.py` still selects EGL. The evaluator source, task configuration, query count, seeds, checkpoint, physics engine, action mapping, and planning parameters are unchanged. Both sides of each Cube parity comparison use the same driver selection, recorded in run metadata.

The complete random-policy check finished in 717.1 seconds. The finite launcher then started the three unchanged Cube reference/wrapper pairs. Reacher seed 44 subsequently also aborted in image rendering under NVIDIA EGL; that pair was restarted under Mesa EGL with its original seed and settings. The completed Reacher seed 42/43 pairs are retained, with their original rendering metadata. Driver selection follows execution failures, not success scores. Incomplete launches and diagnostic outcomes are never included in `official_repro.csv` or `parity.csv`.

The first full Cube attempts under Mesa were interrupted by a newly added driver-information query in the audit observer: PyOpenGL raised error 1281 while `glGetString(GL_VENDOR)` returned `Mesa`. This was an instrumentation error, outside the released evaluator and planning implementation. The unnecessary graphics query was removed. The corrected observer then completed a two-query, 50-step run without errors, after which all three original 50-query seeds were restarted. The observer now records driver selection from launch metadata and makes no graphics-information calls during evaluation. The interrupted attempts are preserved separately and excluded from result tables.

Package versions are recorded under each task's actual launcher in runtime_versions.json. Reacher uses the pre-existing compatibility environment (MuJoCo 3.10.0 and dm-control 1.0.43); the other task launchers resolve MuJoCo 3.12.0 and dm-control 1.0.44. Each reference/wrapper pair shares its task runtime. All use stable-worldmodel 0.0.6 and stable-pretraining 0.1.6.
